# 3.3.0: closing time, display mode, estimated wait

## New

- **Pick when a queue closes.** A date-time picker when creating a queue replaces the fixed 24 hours. It defaults to 24 hours from now and goes up to a year.
- **Display mode** for a tablet, TV or laptop facing the line, linked from the admin page.
  - It shows who is being served, the next few tickets (`?top=N`, default 5), the admin message, the estimated wait and the join link.
  - It needs no admin password and keeps the screen awake where the browser allows it.
- **Estimated wait**, shown per ticket in the line, to each person for their own place, to someone about to join, and on the display.
  - It treats the queue as a single-server queue: by Little's law, the wait at position _p_ is about (_p_ − 1) × the time to serve one person.
  - That time is a moving average (EWMA) of the admin's real serves, counting only time when people were waiting. See [ADR 0003](https://github.com/barakplasma/in-person-queue/blob/3.3.0/docs/adr/0003-wait-time-estimate.md).

## API

- `POST /api/queues` takes an optional `closes` (RFC 3339). If it's in the past or more than a year away, the server answers 400.
- The event stream adds `closes` (unix ms) and `serviceSeconds` (once known).
